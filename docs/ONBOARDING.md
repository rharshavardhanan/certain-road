# Onboarding

One page to get from a fresh clone to knowing what this repo is, what has run and what
has not. Figures live in [`REPO-MAP.md`](REPO-MAP.md), which is generated from evidence;
this page only points at them.

## What it is

A pavement-management decision-support system. It answers "which road segments should be
repaired first, given a fixed budget?", not "where is a pothole?". Camera images go
through YOLOv8s detectors (Model B for three classes, Model P for potholes) to a
vision-estimated PCI per evaluation segment, then to a conformal bound and a budget
optimiser, and finally to an offline HTML dashboard. The design is in
[`design.md`](design.md); the reasons behind every choice are in
[`DECISIONS.md`](DECISIONS.md).

## Install

You need [`uv`](https://docs.astral.sh/uv/). It provides Python 3.12 and every pinned
dependency. Training and inference use Apple's MPS backend; the tests need no GPU.

```bash
uv sync --all-extras --dev
```

## Check it works

```bash
uv run lint-imports   # the stage-isolation contracts
uv run pytest
```

On a fresh clone a few split-leakage tests skip. They need the gitignored image pool,
and each skip message names the script that builds it.

## What has not run, and why

[`REPO-MAP.md`](REPO-MAP.md) §6 gives each task's status and the evidence that decided
it. §10a lists the tasks that have not run (the Webots simulation T13, edge hardware T14
and Chennai footage T15) and what each waits for.

## What a clone does not include

- `data/` and `runs/` are gitignored. The dataset comes from
  `uv run certain-road dataset fetch`; trained weights come from the Kaggle runs. Every
  experiment script needs one or both, and REPO-MAP §11 lists them in rerun order, marking
  the steps that need Kaggle.
- The locked Model P run's image links in `results/LOCKED/` point at this project's
  original machine and do not resolve elsewhere. Its image list, labels and scores are
  committed; see D084.
