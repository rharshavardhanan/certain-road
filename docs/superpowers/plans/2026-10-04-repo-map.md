# Repo map: a generated onboarding document

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `uv run python scripts/repo_map.py` writes `docs/REPO-MAP.md`: what the
system is, which file does what, build order, per-task state with evidence, and what
is left. Every fact is read at build time.

**Architecture:** One stdlib + PyYAML script. An AST pass over `scripts/` recovers
each script's reads, writes, config keys and CLI arguments, and sections 2, 5, 6, 10
and 11 are all derived from that one table. Tunables live in `configs/repo_map.yaml`.

## Brainstorm — what the ask did not state

- **No spec in the repo names T0–T17.** The order comes from `TASK_LOG.md`
  ("**Order:** T0 → …"). Names come from a `RESULTS.md` heading carrying `(Tn)`, else
  a script docstring opening `Tn —`, else the first commit subject naming Tn, else
  "unknown". The source of each name is printed.
- **`TASK_LOG.md`'s progress table is stale** (written 2026-09-22: T6 "blocked",
  T16–T17 "not started"). It is shown as a claim beside the derived status, never
  used as status.
- **`CLAUDE.md` says "No code yet."** Section 1 quotes it verbatim, as asked, and
  follows the quote with a generated count of commits and Python files.
- **D082 exists in the working tree but not at HEAD.** 10b reports D-numbers cited
  but absent from the working-tree log, *and* those written but uncommitted
  (working tree vs `HEAD:docs/DECISIONS.md`).
- **Byte-identical reruns.** The map excludes itself (else its own line count and
  untracked flag change run 2). pytest's duration is stripped. Tests of the script
  never run the full build, which runs pytest, which would recurse.
- **`results/LOCKED/P_india_heldout_run` is 4,640 files.** Directories over a
  configured file count collapse to one row.
- **No magic numbers in code** (project rule): thresholds, stage→script map,
  read-only lane, the args keys shown for training runs all live in config.
- **No commit.** The ask says "stop and show me"; the user's rule is no commit
  unless asked.

## Global constraints

- Read-only: `scripts/eval_video.py`, `exp_video_extent.py`, `score_video_gt.py`,
  their tests, `configs/eval/video.yaml`, `configs/eval/gt/`, `results/video/`.
- No training, evaluation, or GPU work. Running pytest and lint-imports is allowed
  (no test touches the GPU; checked).
- Status strings appear in the script only as the `Status` enum's values.

### Task 1: Extraction core, test-first

- **Goal:** Pure functions recover a script's reads/writes (including
  `root / "results" / "T12"` joins, variables, f-strings as globs), docstring first
  sentences, and a task status from expected paths.
- **Why:** Sections 2, 5, 6, 10 and 11 all stand on this; a wrong read/write split
  silently corrupts the task table and the reproduce order.
- **Files:** `scripts/repo_map.py`, `tests/test_repo_map.py`.
- **Steps:**
  - [x] Tests: joined path with `write_text` is a write · `read_text` / `need(...)`
        literal is a read · base directory of written files is not listed as a read ·
        f-string becomes a glob · config subscripts yield dotted keys · argparse
        arguments with required/default · status: all present -> done, some ->
        partial, none -> not run, none expected -> unknown · docstring first sentence.
  - [x] Run -> fail on import; implement; run -> pass.
- **Done when:** `uv run pytest tests/test_repo_map.py -q` passes; ruff clean.
